## 1. 開発環境

| 項目 | 内容 |
| --- | --- |
| 必須 | Node.js 22 以上、npm |
| 初期化 | `npm install` |
| 開発サーバー | `npm run dev`（http://localhost:5173） |
| 型チェック | `npm run typecheck` |
| 本番ビルド | `npm run build`（成果物は `dist/`） |
| ビルド結果の確認 | `npm run preview` |

### 社内ネットワークでの注意

TLS 検査のプロキシ環境では、`npm install` が `UNABLE_TO_VERIFY_LEAF_SIGNATURE` で失敗することがある。
**TLS 検証を無効にせず**、Node に OS の証明書ストアを使わせる：

```bash
NODE_OPTIONS=--use-system-ca npm install
NODE_OPTIONS=--use-system-ca npm run dev
```

## 2. 公開（GitHub Pages）

### 2.1 仕組み

`main` ブランチへ push すると、`.github/workflows/deploy.yml` が次を自動実行する。

1. 取得 → Node.js 22 の準備 → `npm ci` → `npm run build`
2. `dist/` を Pages の成果物としてアップロード
3. GitHub Pages へデプロイ

`vite.config.ts` は `base: './'`（相対パス）のため、`https://<ユーザー or 組織>.github.io/<リポジトリ名>/` のサブパスでも、リポジトリ名を意識せずに動く。

### 2.2 初回設定（1 回だけ）

1. GitHub にリポジトリを作成し、`main` を push する。
2. **Settings → Pages → Build and deployment → Source** を **GitHub Actions** にする。
3. **Actions** タブでワークフローが成功したことを確認する（初回は数十秒〜数分）。
4. Pages の URL にアクセスして表示を確認する。

### 2.3 更新

コードを変更して `main` に push するだけで、自動で再公開される。手動実行は **Actions → Deploy to GitHub Pages → Run workflow**。

## 3. 公開範囲・費用

> 以下は一般的な理解にもとづく。料金・制限は変わりうるため、公開前に GitHub 公式ドキュメント（GitHub Pages、GitHub Actions の課金）で確認すること。

| 項目 | 内容 |
| --- | --- |
| 無料で使える条件 | **public リポジトリ**（GitHub Free）。private で Pages を使うには有料プランが必要 |
| 公開範囲 | Pages のサイトは、プランや設定によっては private リポジトリでも**誰でも閲覧できる**。社内限定にしたい場合は Enterprise Cloud のアクセス制御などを確認 |
| サイズ・転送量 | 静的ファイル合計は約 4 MB。上限（サイト 1 GB、転送量は目安月 100 GB）に十分余裕がある |
| Actions | public は無料。private はプランごとの無料枠内（ビルドは数秒） |
| 会社として | 社外に公開してよい内容かどうか（解説文の校正状況、ライセンス表示）を事前に確認する |

## 4. 外部依存と保守

| 依存 | 影響 | 確認・対応 |
| --- | --- | --- |
| Wikipedia REST API | 写真・要約。止まっても星図に切り替わる | 定期的に写真の表示を確認。API の仕様変更に注意 |
| Google Fonts | 見た目のフォント | 失敗時は代替フォント |
| npm パッケージ | React、GSAP、astronomy-engine など | 半年に 1 回程度更新し、`npm run build` と主要操作を確認。`package-lock.json` はコミットする |
| 星データ | 静的 JSON（d3-celestial 由来） | 更新は基本不要。差し替える場合は `public/data/` と `src/data/loadCatalog.ts` の形式を確認 |

### 保守の注意

- 天体位置は実行時に計算されるため、日付が進んでもデータ更新は不要。
- 恒星の固有運動は考慮していない（数十年規模の使用では見た目の差は小さい）。
- 解説（`src/data/*.en.ts`）は手書きのため、内容の修正はこれらのファイルを編集する。

## 5. 公開前チェックリスト

- [ ] `npm run typecheck` と `npm run build` が成功する
- [ ] 解説文（神話・数値）を一次資料で校正した、または未校正である旨を明示した
- [ ] 公開範囲（public／private、Pages のアクセス制御）を確認した
- [ ] 出典・ライセンス表示（開始画面のフッター、README）を確認した
- [ ] Edge 以外のブラウザ、スマートフォンの実機で表示を確認した
- [ ] 秘密情報がリポジトリに含まれていない

## 6. 障害時の対応

| 症状 | 確認・対応 |
| --- | --- |
| Pages が 404 | Settings → Pages の Source が「GitHub Actions」か。Actions が成功しているか |
| 画面が真っ白 | ブラウザのコンソールを確認。`data/*.json` の 404 がないか（`base` の設定、ビルド成果物に `dist/data/` があるか） |
| 星座カードの写真が出ない | ネットワークと Wikipedia への接続を確認。出ない場合は自作の星図が表示される（想定内の動作） |
| ビルドが失敗 | `npm ci` を再実行。Node のバージョンが 22 以上か。型エラーは `npm run typecheck` で確認 |
| `npm install` が証明書エラー | §1 の `NODE_OPTIONS=--use-system-ca` を使う |
